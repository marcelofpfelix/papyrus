# Demo-only local surface

This file records Papyrus repo files that are intentionally local to the demo
site and should not be treated as reusable theme/package defaults without a
separate review.

## Local demo routes

These files stay under `src/pages` because the Papyrus package site needs
showcase-specific copy, fixture wiring, or profile links that should not be
inherited by every consuming site:

- `src/pages/index.astro`: Papyrus package homepage with demo posts, projects,
  docs, and notes.
- `src/pages/about.astro`: demo about page with Papyrus-specific link previews
  and project card examples.
- `src/pages/projects.astro`: demo project page fed by `public/demo/site-data.json`
  and a visible structured-data example.
- `src/pages/metadata-demo.astro`: standalone post-layout metadata fixture.
- `src/pages/posts/cv-profile.astro`: standalone CV/profile feature article.
- `src/pages/posts/theme-profiles.astro`: standalone theme-profile feature
  article.
- `src/pages/profile/index.astro`: Papyrus demo profile using repo-specific
  source links and print-version links.

If any of these routes start representing reusable behavior rather than demo
copy, promote the generic part into `src/template/pages`, `src/components`, or
`src/utils` and keep only the demo-specific data/copy here.

The demo inherits `/profile/print` and `/profile/ast` from
`src/template/pages/profile`; local copies were removed because the template
already reads the same `src/data/profile.toml` input.

## Reusable injected routes

The reusable site routes live under `src/template/pages` and are injected by
`src/integration.ts`. Consuming sites inherit these unless they provide a local
override:

- `/`
- `/about`
- `/posts`
- `/posts/timeline`
- `/posts/[...slug]`
- `/projects`
- `/profile`
- `/collections`
- `/collections/[slug]`
- `/collections/[collection]/[...slug]`
- `/search`
- `/tag`
- `/tag/[tag]`
- `/404`
- `/rss.xml`
- `/robots.txt`

## Demo content and data

These files support the package demo site and should not be shipped as package
payload:

- `src/content/posts/**`: demo posts, docs collection content, food collection
  fixtures, and the hidden-post fixture.
- `src/data/demo-*.ts`: demo navigation, post metadata, and home-page limits.
- `src/data/profile.toml`, `src/data/profile.ts`, and `src/data/profile-links.ts`:
  demo profile/CV data.
- `public/demo/**`: demo source examples, generated fixture trees, diagrams,
  cover images, and demo site data.
- `public/assets/img/user/**`: demo profile images.
- `public/images/**`: demo cover/brand images.

The npm `files` list should keep these out of the published package. Check with
`pnpm pack --dry-run` after changing package boundaries.

## Generated public artifacts

These are generated for the demo site and should not become hand-maintained
source of truth:

- `public/pagefind/**`: generated by `pagefind --site dist`.
- `public/rss/tags/**`: generated by `scripts/generate-tag-rss.mjs`.
- `public/ai/**`: generated by `scripts/generate-ai-indexes.mjs`.
- `public/cv/resume.json` and `public/cv/profile.md`: generated by
  `scripts/export-cv.mjs`.
- `public/llms.txt` and `public/llms-full.txt`: generated by
  `scripts/generate-llms.mjs`.

The top-level `/rss.xml` should come from `src/template/pages/rss.xml.ts`, not a
tracked `public/rss.xml`.

## Review triggers

Review this surface when:

- a consuming site needs a feature that only exists in `src/pages`;
- a public demo route and a template route drift in behavior;
- generated files become stale or are checked in only to satisfy old tests;
- the package tarball starts including demo pages, demo content, or public
  generated artifacts.
